# M3 五类花卉模型评估报告

## 结论与适用范围

本次原型选定 **EfficientNet-B0 + 线性分类头**，选择依据是冻结验证集 macro F1（各类别 F1 的平均值），不是独立测试分数。其 550 张测试图片的准确率为 **92.18%**、macro F1 为 **0.9200**；MobileNetV3-Small 对照模型分别为 **90.00%**、**0.8984**。两者均达到预设闭集 macro F1 ≥ 0.80 的目标。

模型只在 `daisy`、`dandelion`、`roses`、`sunflowers`、`tulips` 五种数据集类别内做选择。它不是校园全部植物识别，也不提供精确物种鉴定。**两个 v1 模型的阈值均为 0.0，正常输入不会因分数低被拒识；当前服务只有过小或近乎纯色的低图质图像可被提前标为无法确认。** 非目标植物、垃圾、人物等开放集，以及校园实拍尚未评估。

报告依据为仓库冻结 JSON 和 2026-09-19 的文件复核。本次收尾没有重新训练、调整阈值或重跑独立测试。

## 数据、去重和划分

数据来自 [TensorFlow 官方 flower_photos 示例](https://www.tensorflow.org/tutorials/load_data/images)。压缩包含 3,670 张图片，逐图作者及原始地址保存在 [署名清单](../data/FLOWER_PHOTOS_ATTRIBUTION.txt)。

| 类别 | 训练 | 验证 | 独立测试 |
| --- | ---: | ---: | ---: |
| daisy / 雏菊类花卉 | 443 | 95 | 95 |
| dandelion / 蒲公英类花卉 | 628 | 135 | 135 |
| roses / 蔷薇属花卉 | 449 | 96 | 96 |
| sunflowers / 向日葵类花卉 | 488 | 105 | 104 |
| tulips / 郁金香类花卉 | 558 | 120 | 120 |
| 合计 | 2,566 | 551 | 550 |

完全相同的 SHA256 图片删除 3 张，保留 3,667 张。64 位 dHash、汉明距离 ≤ 4 检出 13 对相近图片，合并为不可拆分的连通组后形成 3,654 组；同组跨划分重叠为 0，保留图片不存在完全相同的 SHA256。随机种子为 `20260916`。

删除项中有一张 `tulips/15922772266_1167a06620.jpg` 与 `roses/15922772266_1167a06620.jpg` 完全相同，按固定遍历规则保留后者。此规则避免了完全重复图片泄漏，但没有解决原始数据的植物学标签质量问题。dHash 分组也不能保证所有相似拍摄场景都被发现；尚未按摄影者、拍摄地点或时间做独立划分。

详细依据：[数据审计](data_audit_v1.json)、[完整划分](../data/flowers_split_v1.json)、[实验方案](../data/experiment_v1.json)。

## 训练与选择过程

两模型使用 TorchVision `IMAGENET1K_V1` 预训练权重，主干冻结为推理模式，训练多类别 Logistic Regression 分类头。没有进行整网微调。候选 `C` 为 0.01、0.1、1、10；MobileNet 选中 0.1，EfficientNet 选中 0.01。

模型选择和阈值只使用验证集。阈值规则要求接受样本至少 30 张、接受准确率至少 90%，优先覆盖最多样本。两者在接受全部验证图片时已超过 90%，因此选择 `0.0`，验证及测试覆盖率都为 100%。这不能证明模型能拒绝类别外图片，也不能把 softmax 分数当作正确概率。

冻结主干提前提取了三个划分的特征，但拟合分类头仅使用训练子集；验证特征只用于参数/阈值/模型选择。`selection_v1.json` 先冻结两份验证报告哈希和首选模型，之后生成各模型的独立测试报告。源码检查未发现用测试指标选择模型或阈值的分支。收尾复核确认冻结的验证报告哈希仍一致；这些本地证据不等同于第三方预注册。

训练、离线 ONNX 评估和服务共用预处理函数：EXIF 校正 → RGB → 短边 256 双线性缩放 → 中心 224 裁剪 → ImageNet 均值/标准差归一化。输出为五类 logits，排序分数经过 softmax。现有 FP32 导出没有量化；独立测试的 ONNX 与 PyTorch Top-1 一致率均为 100%，macro F1 差值均为 0。

| 指标 | MobileNetV3-Small | EfficientNet-B0（选定） |
| --- | ---: | ---: |
| 验证准确率 | 91.11% | 94.37% |
| 验证 macro F1 | 0.9090 | 0.9426 |
| 测试准确率 | 90.00% | 92.18% |
| 测试 macro F1 | 0.8984 | 0.9200 |
| 测试正确 / 总数 | 495 / 550 | 507 / 550 |
| 测试接受覆盖率 | 100% | 100% |
| 阈值 | 0.0 | 0.0 |
| ONNX 大小 | 3,729,596 bytes | 16,047,581 bytes |

| CPU 前向 p50 | 4.87 ms | 24.36 ms |

性能环境为本机 Apple M2、8 GB、macOS arm64、Python 3.12.6、PyTorch 2.8.0；ORT 使用 CPUExecutionProvider、1 线程、batch size 1，预热 5 次、测量 50 次。前向延迟使用同一张测试图片，不包含解码、裁剪、子进程启动、文件校验、模型加载、排队和 HTTP。峰值 RSS 含同时加载的 PyTorch 和 ORT，**不是生产 worker 的独立内存**；这些结果也不是 Debian/首尔服务器实测值。

完整机器可读证据：[MobileNet 验证](mobilenet_v3_small-validation.json)、[测试](mobilenet_v3_small-test.json)、[EfficientNet 验证](efficientnet_b0-validation.json)、[测试](efficientnet_b0-test.json)、[选择记录](selection_v1.json)。

行是真实标签，列是预测标签：

| 真实 \ 预测 | daisy | dandelion | roses | sunflowers | tulips |
| --- | ---: | ---: | ---: | ---: | ---: |

EfficientNet 共错 43 张，其中 roses 与 tulips 双向混淆占 16 张。以下为原报告记录的高分错误，说明分数高仍可能判断错误；这里没有据此调整模型或阈值：

| --- | --- | ---: |
| `daisy/2561371688_c80a4fe957_n.jpg` | daisy → dandelion | 0.9837 |
| `tulips/164578909_51f245d3fa_n.jpg` | tulips → roses | 0.9319 |
| `tulips/4604238410_bcec9da4a0_n.jpg` | tulips → roses | 0.8454 |

所有错误样本保存在各测试 JSON 的 `failure_cases`，图片本身在本地数据集目录；逐图来源可在署名清单按文件名查询。上述归因仅为类别统计，没有臆测具体图片的视觉错误原因。
