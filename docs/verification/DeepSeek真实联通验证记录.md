## 操作与原生界面验收

环境为 macOS、微信开发者工具 Stable 2.02.2608070、基础库 3.7.12、iPhone 12/13 模拟器。小程序连接 `http://127.0.0.1:8000/api/v1`，使用既有开发模拟账号；不是手机真机或真实微信登录验收。

1. 使用前一轮从原生工具上传的公开雏菊样例；本机 EfficientNet ONNX 已真实推理完成，候选为雏菊类，原图仍在有效期内。样例仅用于连通性，不能证明植物识别准确率。
2. 从“AI 识别”结果进入“AI 解读本次识别结果”，确认外发告知、初始 5 / 5 额度与默认关闭的附图开关。
3. 保持不附图，勾选数据分享范围，确认原生弹窗。建立会话不会自动发出问题；主动发送一条简短问题后，看到等待、完成和文字回答。
4. 第一条回答解释候选与不确定性，并建议多角度核对。页面显示“本轮仅使用文字结果与对话”；已用 1、处理中 0、剩余 4。
5. 返回原结果，创建第二个会话，主动开启附图，再次勾选并确认包含图片的分享范围。
6. 第二条要求结合图片简短说明外观与局限。回答描述白色花瓣、黄色花心及类别范围局限；页面显示“本轮使用了原图与文字结果”，已用 2、处理中 0、剩余 3。
7. 独立查询数据库安全元数据，确认 `used_image=false/true` 分别与界面一致；没有自动重发或额外试探调用。

原生工具操作中修复了确认按钮文案超出四字限制的问题（[腾讯交互 API 文档](https://intl.cloud.tencent.com/zh/document/product/1219/68021)）：改为“同意继续”，增加弹窗失败提示与锁恢复，避免失败后无法再次确认；重复、离页、换账号回调不创建额外会话。前端完整回归 **214 / 214** 通过。开启真实 Key 后的自动回归不调用外部模型。

## Key 存储与本机运行

- Key 仅写入被 Git 忽略的 `backend/.env` 中的 `DEEPSEEK_API_KEY`；文件权限为 `0600`，仅当前所有者可读写。这是访问权限限制，不是文件加密。
- 用户提供的原始凭据文件同样设置为 `0600`。不复制到小程序、文档、提交、服务器环境或部署归档。
- 精确凭据扫描检查源码、Git 暂存内容及 7 份本机运行日志，没有发现该 Key。扫描只输出通过状态，不输出值。
- 本机 `LLM_ENABLED=1`，后台网关启用；API、花卉、河道、LLM 四个进程运行，数据库和健康检查正常。
- 为控制首次联通消耗，两个请求执行期间全站每日调用上限为 2、单次输出上限为 256 token。
- 交付给用户继续测试时，本机限制调整为：**每账号每日 5 个成功回合、全站每日最多 10 次提交、每日 100000 token 预算、单次输出最多 600 token、并发 1**。修改配置不发出请求，不重置已用额度。
- 失败不占成功回合，但已外发的尝试可能收费；全站限制统计本平台，不涵盖同一 Key 在其他应用中的使用。

继续测试：打开 HYHQ → AI 识别 → 完成花卉或河道任务 → AI 解读 → 确认分享范围 → 主动发送；历史入口在“我的 AI 解读”。当日额度耗尽后等待北京时间零点重置。原图过期后可重新上传，也可建立不附图的会话。

本机控制脚本与日志保留在被忽略的 `.runtime/local-test/`。如需完全停止本地测试，可运行其中的“停止本地测试.command”；后台也可单独关闭网关。
