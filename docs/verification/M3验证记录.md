### 本次修复

1. 模型管理动作补充 change 权限校验，只读 staff 不能通过后台 POST 启停模型。回归同时验证有权限的管理员可以执行。
2. 任务领取后图片资产行被清理或删除时，保存 `ASSET_EXPIRED`；消费者继续处理后续任务。
3. 个人记录页在卸载、会话切换或 401 后拒绝旧异步响应，清空无效分页地址；删除后不保留旧私有图片预览。
4. 同一账号重新登录期间的上传操作可以正确结束忙碌状态。
5. 当前版本的范围和历史结果显示“候选参考／未启用低分拒识”，避免阈值 0 与界面承诺不一致；五篇原始科普稿同步订正。
6. 训练脚本在覆盖冻结证据前拒绝重跑，提供独立复现输出目录，保护已提交的 v1 结果。

## 3. 真实 HTTP 与 CPU 推理联调

使用原生小程序的数据访问代码配合 wx mock，连接实际 Django API、PostgreSQL 和独立 ONNX 工作进程：

```bash
HYHQ_EXPECT_RECOGNITION=1 node miniprogram/tests/live-smoke.js
HYHQ_EXPECT_RECOGNITION=1 HYHQ_TEST_IMAGE=/absolute/path/public-flower.jpg node miniprogram/tests/live-smoke.js
```

两种调用均通过：

- 公开花卉照片真实推理返回 `succeeded / recognized`，前端展示候选参考与所用模型版本。
- 1 像素测试图片返回 `succeeded / uncertain / LOW_IMAGE_QUALITY`，空候选，无伪造类别。
- 识别记录可读取私有缩略图、保留历史模型版本；删除任务后图片不可访问，当前预览清空。
- 开发登录、昵称/头像、收藏/历史/游览、隐私开关、跨账号隔离、退出和注销原流程仍通过。
- 联调账号及其图片均在脚本结束时删除，不遗留演示用户资料。

另用实际两个花卉模型执行版本联调：EfficientNet 推理 → 切到 MobileNet 推理 → 停用 → 恢复 EfficientNet。两个模型均成功，候选关联的已发布文章标签匹配，停用后的 health 开关关闭，首次历史结果保持不变。详见 [版本回退联调原始记录](M3版本回退联调.json)。

## 4. 本机资源观察

| 单次诊断 | MobileNetV3-Small | EfficientNet-B0 |
| --- | --- | --- |
| 独立 CPU 运行时从导入前到结果 | 138.39 ms | 353.38 ms |
| 独立运行时峰值 RSS | 103.22 MiB | 177.70 MiB |
| 实际 worker 记录的任务执行耗时 | 244 ms | 415 ms |
| 创建任务到轮询结果并读取科普 | 680.20 ms | 915.72 ms |

这些是每个模型各一次本机诊断，**不是 p95、负载测试或首尔服务器性能承诺**。第一项不包含 Python 解释器启动；独立运行时不导入 Django/PyTorch。实际 worker 耗时包含子进程启动与加载；最后一项不包含上传时间。详见 [运行资源检查](M3运行资源检查.json)。原模型报告中的前向 p95 只衡量计算，训练/评估进程 RSS 也不能当作推理进程 RSS。
