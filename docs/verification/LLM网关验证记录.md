## 自动化验收

环境：macOS、Python 3.12、Django/DRF、真实本机 PostgreSQL（端口 55432），前端 Node 内置测试运行器。测试使用独立临时数据库与媒体目录，不修改 `hyhq_local` 中的手工测试记录。

```bash
# 当前工作区的隔离测试包装器（.runtime 不进入 Git）
HYHQ_LLM_TEST_SUFFIX=suite .venv/bin/python .runtime/run-llm-check.py test --noinput
HYHQ_LLM_TEST_SUFFIX=check .venv/bin/python .runtime/run-llm-check.py makemigrations --check --dry-run
npm --prefix miniprogram test
git diff --check
```

新检出环境可配置具有测试库创建权限的本机 PostgreSQL 后，从仓库根目录运行 `scripts/manage.sh test --noinput`；测试命令不会部署服务器。运行回归时保持 `LLM_ENABLED=0`、真实 Key 为空。

新增后端测试分布：`llm.tests` 30、`llm.tests_provider` 30、`common.tests_llm_integration` 7、`common.tests_llm_http` 2。

真实 HTTP 测试通过 `LiveServerTestCase` 启动本机 HTTP 服务，以 `urllib` 发出开发登录、multipart 上传、Bearer 会话与问答请求。识别完成结果使用明确标注的测试数据，外部模型始终替换为模拟回复，并阻止底层外网调用。

实际验证：五轮成功、第六轮 429；重放不新增任务/调用；越权 404；附图压缩与去 EXIF；删除/重登不恢复当日额度；上游响应期间删除源识别记录不恢复会话、答案和图片，已发生用量仍保留。

跨模块覆盖：账号注销、源记录删除、图片准备后失效、管理员只读权限、清理 dry-run 与真实清理、健康检查和网关状态一致。所有 provider 异常和进程超时均使用合成输入，没有把真实用户内容发给外部服务。

本机日志：`.runtime/llm-full-backend.log`、`.runtime/llm-full-frontend.log`、`.runtime/llm-http-tests.log`；临时数据库和 HTTP 测试进程由测试框架销毁。

## 启用与手工测试

1. 在本机被 Git 忽略的 `backend/.env` 填写 `DEEPSEEK_API_KEY`，设置 `LLM_ENABLED=1`、`DEEPSEEK_MODEL=deepseek-flash`。不要将 Key 写入小程序或提交仓库。
2. 重启本地 API 和 worker，使进程重新加载环境变量。本机便捷脚本为 `.runtime/local-test/停止本地测试.command`、`启动本地测试.command`；通用命令见部署 README。
3. 打开本机管理后台 →「AI 网关配置」→ 启用。默认每账号每天 5 轮成功、10 次提交；全站每天 200 次尝试、100 万 token 预算；可下调，不可把用户回合提高到 5 以上。
4. 在小程序登录并完成一条花卉识别或河道观察 →「AI 解读本次识别结果」→ 阅读分享范围 → 可选附图 → 建立会话 → 主动发送问题。
5. 「我的 → 我的 AI 解读」可查看会话、额度和删除。停用网关后已有会话仍可查看，不能发送新问题。
