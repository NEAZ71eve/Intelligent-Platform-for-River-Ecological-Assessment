## 使用规则

- `[ ]` 表示未验收，`[x]` 表示已有可复查证据并通过验收。
- M0～M4 属于核心演示版；M5 是增强版，不阻断核心交付。
- 阶段依赖表示集成验收顺序；内容整理、数据盘点、模型实验可在不依赖账号能力的情况下提前进行。
- 验收证据保存在 `docs/verification/`，记录环境、日期、操作、预期、实际结果及必要截图；实现时再创建该目录。

## M0：冻结范围，验证账号与访问链路

依赖：现有小程序账号、域名及服务器的实际配置。缺少访问资料时先记录待办，不把条件默认写成已满足。

- [ ] **M0-01 确定示范区域与内容规模**  
  验收：记录城市、校园、首批地点和河湖清单；建议 10～20 个点位、2～3 个监测站。未取得资料时明确使用示范数据，不虚构真实监测关系。
- [ ] **M0-02 盘点个人主体账号能力**  
  验收：记录 AppID、账号类目、可用接口、成员/体验权限及备案状态；项目文档中 AppID 按需要脱敏，密钥不入库。
- [ ] **M0-03 验证 HTTPS 与合法域名配置**  
  验收：请求、上传、下载所需域名可按目标运行方式配置，证书链有效；若不通过，记录原因及选定的接入或部署调整方案。依赖 M0-02。
- [ ] **M0-04 完成最小真机链路**  
  验收：在计划答辩的手机和网络上完成登录、请求测试接口、上传图片及读取受控结果；记录是否依赖调试模式。最终演示方式尚不可用时本项不得勾选。依赖 M0-03。
- [ ] **M0-05 选择天气与空气质量数据源**  
  验收：实际调用目标地区样例，记录字段、单位、AQI 标准、更新时间、额度、费用和使用许可；明确哪些数据缺失以及失败回退方式。
- [ ] **M0-06 盘点植物数据与模型候选**  
  验收：列出拟支持类别、数据来源、许可、样本数和两个候选分类模型；暂不承诺尚未验证的类别效果。
- [ ] **M0-07 冻结首版范围和测试口径**  
  验收：确认植物优先、LLM 默认关闭、示范数据边界、目标规模及性能验收值；待决事项均有后续任务承接。

**阶段交付：** 范围清单、账号与网络验证记录、数据源清单、模型候选清单。  
**通过条件：** 目标演示访问路径实际可用，或已完成调整并重新验证。

## M1：建立工程、数据与权限底座

依赖调整：按用户要求，M0 真实数据源暂缓，天气、空气与河湖统一使用明确标注的模拟数据。真实微信身份和外部访问验收仍依赖 M0-04。

- [x] **M1-01 初始化代码目录与依赖**  
  验收：建立小程序、后端、推理、部署和文档目录；锁定兼容版本；提供无真实密钥的配置示例，忽略数据库、上传文件、模型大文件和本地密钥。
- [x] **M1-02 搭建后端与数据库**  
  验收：空数据库可以完成迁移、创建管理账号并访问健康检查；管理端可登录，重复启动不会破坏数据。
- [x] **M1-03 建立核心领域模型**  
  验收：包含区域、地点、水体、监测站、指标、来源、观测、内容、路线和用户记录；能够表达一条河多个监测站，并定义必要索引和去重规则。
- [ ] **M1-04 实现登录、会话和权限（本地实现及模拟联调通过，真实微信验证待 M0）**  
  验收：微信登录建立业务会话；昵称头像主动设置；游客可浏览；用户仅访问自己的记录，管理员角色在服务端生效。
- [x] **M1-05 统一 API 与数据契约**  
  验收：版本前缀、错误代码、分页、时间格式、来源与质量状态统一；至少提供地点和观测查询样例及契约说明。
- [x] **M1-06 建立文件与隐私生命周期**  
  验收：图片验证类型/体积/解码尺寸并移除不必要元数据；文件访问鉴权；保留期限写入配置与隐私说明，清理命令可验证。
- [x] **M1-07 建立模拟生成与数据导入**  
  验收：固定种子可生成相同序列；支持正常、浑浊、缺失三种场景；重复执行不重复入库；历史导入保留原始时间与来源。
- [x] **M1-08 建立任务与运行日志**  
  验收：识别任务具有排队、处理、成功、失败状态；后台任务可记录运行批次、耗时和错误；密钥与用户敏感字段不进入日志。

**阶段交付：** 可运行后端、数据库迁移、登录与权限、种子资料、模拟数据及 API 说明。详见 [M1 验证记录](verification/M1验证记录.md)：44 项 PostgreSQL 后端测试、17 项小程序测试、真实 HTTP + wx mock 联调通过。  
**通过条件：** 管理员能维护数据，用户身份和数据来源能够贯穿请求到数据库。

## M2：实现用户端与管理端核心业务

依赖：M1；页面骨架与静态内容可提前准备。

- [ ] **M2-01 实现五个一级入口与通用状态**  
  验收：首页、生态导览、AI 识别、科普智游、我的可导航；主要页面有加载、空数据、错误和重试状态。
- [ ] **M2-02 实现地区选择、天气与空气质量**  
  验收：按需触发定位，拒绝后可手动选择；显示来源和时间；真实数据不可用时不自动伪装成模拟实况；当前城市与示范区分别标明。
- [ ] **M2-03 实现气象预警展示**  
  验收：区分无预警、请求失败、过期缓存；预警更新或取消后界面同步；显示发布方与有效时间，不与模拟阈值提示混淆。
- [ ] **M2-04 实现静态生态导览与地点详情**  
  验收：点位绑定底图版本和相对坐标；不同屏幕、缩放及图片留白时点位准确；支持列表进入详情，管理员修改点位后可见。
- [ ] **M2-05 实现智慧河湖页面**  
  验收：按水体/监测站查看四项指标、单位、时间和历史趋势；模拟标记明显，缺失值形成断点；不输出完整官方水质类别。
- [ ] **M2-06 实现数据中心与查询聚合**  
  验收：支持指标卡和时间范围查询；按来源筛选，长区间限制点数或聚合；混合来源请求不会生成无说明的汇总结果。
- [ ] **M2-07 实现科普内容与预设路线**  
  验收：文章可按标签浏览并关联地点/植物；路线有有序节点；仅发布状态内容对外可见，图片和文字出处有记录。
- [ ] **M2-08 实现个人记录与反馈**  
  验收：收藏可新增/取消；浏览与用户自记游览可查询、删除、跳转；重复操作不产生重复收藏；内容删除后有明确提示；反馈可在后台处理。
- [ ] **M2-09 实现管理端操作与统计**  
  验收：能够维护用户权限、内容、地点、监测站、指标及模拟场景；统计定义明确，能够追溯关键管理修改；真实与模拟数据可区分。
- [ ] **M2-10 实现隐私设置与注销**  
  验收：用户协议/隐私说明与实际收集行为一致；可关闭可选记录；注销后旧会话失效，关联记录和文件按既定规则处理。

**阶段交付：** 可操作的小程序业务页面及管理后台。  
**通过条件：** 从管理员发布内容到用户浏览、收藏、删除记录的流程完整；定位和上游失败不阻断公开内容浏览。

## M3：接入并评估首个真实图像模型

依赖：M0-06、M1 的识别任务与文件机制；数据整理和离线实验可与 M2 并行。

- [ ] **M3-01 冻结识别类别与数据集划分（公开数据完成，校园实拍与非目标图片待补）**
  验收：完成数据去重与训练/验证/测试划分；保留校园实拍测试样本和非目标图片；记录类别数量及许可，最终测试集不参与调参。
  已完成：五类 flower_photos、3,667 张去重照片、2,566/551/550 分组划分与逐图署名；原始实验清单已冻结。
- [x] **M3-02 完成两个模型的离线对比**
  验收：在统一类别与数据划分下记录准确率、宏平均 F1、混淆矩阵、延迟和内存，保存模型来源、训练/适配步骤及失败案例。
  结果：验证集选 EfficientNet-B0，测试准确率 92.18% / macro F1 0.9200；MobileNetV3-Small 为 90.00% / 0.8984。详见 [模型评估报告](../inference/reports/M3模型评估报告.md)。
- [ ] **M3-03 转换并验证 CPU 推理制品（本机 CPU 通过，首尔服务器待验收）**
  验收：服务器可以加载选定模型；预处理、标签顺序与离线版本一致；转换或量化后的效果差异有记录，制品具有版本与校验值。
  已完成：两份 ONNX、SHA-256、预处理/类别顺序清单；测试集上转换前后 Top1 一致率 100%，未量化。独立 CPU 进程本机资源检查已记录。
- [x] **M3-04 实现受限识别工作进程**
  验收：并发初始为 1，限制队列与执行时间；异常图片和模型错误产生明确失败；重启后任务恢复或终止，不永久处理中。
  已完成：共享执行锁、子进程硬超时、队列限额、遗留任务终止、私有图片生命周期及错误处理自动验证。
- [ ] **M3-05 实现小程序识别交互（代码与真实 HTTP 联调通过，微信工具/真机待验收）**
  验收：用户可选图上传、查看排队/处理中状态、读取真实模型结果；结果可关联科普并进入个人识别记录，不使用固定答案冒充推理。
- [ ] **M3-06 实现不确定结果与模型管理（机制完成，实际低分/未知对象拒识待后续评估）**
  验收：阈值基于验证集确定；低分或不支持类别返回明确提示；后台可登记、启停及回退模型版本；历史记录保留原模型版本。
  已完成：模型登记、校验、管理员权限、启停与回退、历史快照、低图质拒识及可配置阈值。v1 按预设验证规则得到阈值 0，不做低分拒识；未知对象可能高分误判，界面明确说明，不能将此项整体勾选。

**阶段交付：** 本地真实图像推理、前后端流程、可复现制品与评估报告；见 [M3 验证记录](verification/M3验证记录.md)。代码收尾不替代上述真实场景验收。
**通过条件：** 分类范围、效果与限制可说明；坏图片、非目标图片和服务故障均可处理。

## M4：部署、联调与答辩交付

依赖：M0～M3；部署脚本与说明可提前编写。

- [ ] **M4-01 完成服务器部署与进程管理**  
  验收：按说明部署 Nginx、业务服务、PostgreSQL、推理和定时任务；密钥安全配置；重启服务器后服务恢复，数据库及模型接口不对公网直接开放。

- [ ] **M4-08 准备答辩版本与可复现演示材料**  
  验收：固定代码版本、模型版本和模拟种子；准备演示账号、场景与脚本；断网时使用明确标注的缓存/演示资料，并说明哪些能力不能实时执行。

**阶段交付：** V1.0 核心演示版与完整交付材料。  
**通过条件：** 所有核心验收完成，关键问题已修复；公开发布若未验证，仍明确标记为未完成。

## M5：可选增强任务

依赖：不影响 V1.0 交付；以下子项可分别实施。启用面向用户的新功能时同步更新界面、隐私说明与验收范围。

- [ ] **M5-01 增加垃圾识别**  
  验收：先识别物品再映射到明确地区的分类规则；独立记录数据集、模型效果与不确定结果，避免把植物模型直接当作垃圾模型使用。
- [ ] **M5-02 实现资料检索式问答入口**  
  验收：通过关键词、标签和地点检索已发布资料，返回可核对来源；无资料时明确说明，不生成无依据的实时环境结论。
- [ ] **M5-03 实现 LLM 网关与外部 API 开关**  
  验收：配置服务方、模型、密钥引用、超时、用户额度、输入输出长度及全局预算；禁用或无额度时确实不发起外部请求，失败回退可验证。依赖 M5-02。
- [ ] **M5-04 完成本地 Qwen3.5-2B 量化实验**  
  验收：记录运行时、量化版本、上下文、首字延迟、总耗时和整机峰值内存；与业务/图像模型同时运行时验证；不达标则保留报告并维持关闭。依赖 M5-02，网关集成依赖 M5-03。
- [ ] **M5-05 接入真实监测或额外历史数据**  
  验收：核实许可和覆盖范围，完成单位、时区、地点及来源映射；导入可去重，图表不会混淆历史与实时数据。
- [ ] **M5-06 接入真实地图与到访核验**  
  验收：明确地图数据许可、坐标系、定位授权及核验规则；通过固定点位检查偏移；保留定位拒绝时的导览能力。
- [ ] **M5-07 增加用户评论与举报**  
  验收：先确认个人主体对应能力与服务范围，再实现发布、审核、举报、删除及管理记录；未通过条件核实不开放入口。
- [ ] **M5-08 准备公开发布**  
  验收：依据实际启用功能确认服务类目、备案、域名、隐私及 AI 相关材料，完成平台审核和发布验证；演示通过不能替代本项验收。

## 首轮建议执行顺序

1. M0-01、M0-02：明确区域，盘点账号和现有资源。
2. M0-03、M0-04：优先解决 HTTPS、合法域名和真机登录上传链路。
3. 同步完成 M0-05、M0-06：选定实际数据来源，盘点植物数据。
4. M0-07 通过后推进 M1；M2 页面开发与 M3 离线模型实验可并行。
5. M4 验收核心版后，再按需要启用 M5。

## R1：朋友仓库河道功能整合

来源与适配说明见 [整合说明](朋友仓库整合说明.md)。本阶段不替代 M2/M4，也不等于真实水质监测或垃圾材质分类。

- [x] **R1-01 模型适配**：固定来源和 SHA-256，独立登记检测模型，仅开放 class 9；保留花卉模型，支持停用/恢复。
- [x] **R1-02 评估后端**：私有任务、可选同坐标系定位、公开水体关联、冻结模型和教学规则版本；空检测不评分。
- [x] **R1-03 小程序本地流程**：上传、检测框、规则说明、历史记录、删除，以及不定位/定位拒绝后的页面状态（自动测试与 wx mock；真机见 R1-05）。
- [x] **R1-04 整合验证**：PostgreSQL 125 项、前端 58 项、真实 ONNX + HTTP 联调、共享容量与锁、权限、注销和过期清理，见 [验证记录](verification/河道整合验证记录.md)。
- [ ] **R1-05 微信和服务器验收**：开发者工具/真机定位与隐私授权、布局和目标服务器性能，依赖实际账号与部署。
- [ ] **R1-06 真实河道独立评估**：代表性实拍、范围外场景与人工标签；不使用训练拼图结果代替实际精度证据。
